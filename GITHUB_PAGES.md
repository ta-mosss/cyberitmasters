# GitHub Pages deployment

This project is configured for GitHub Pages as the **static React/Vite frontend**.
Firebase Authentication, Firestore, Storage and server-side functions remain backend services and are not executed by GitHub Pages.

## First local install

Use Node 20, 22, or 24.

```powershell
npm install
npm run build
npm run phase3:check
```

A real `package-lock.json` should be generated by `npm install` and committed to Git. CI uses `npm ci` and will fail if the lockfile is missing or out of sync with `package.json`.

## GitHub setup

1. Push the project to GitHub.
2. Use the `main` branch.
3. In **Settings → Pages**, select **GitHub Actions** as the source.
4. The included `.github/workflows/deploy-pages.yml` builds and deploys `dist/`.
5. For a project site, the workflow automatically sets `VITE_BASE_PATH` to `/<repository-name>/`.
6. If using a custom domain or a GitHub user/organization site repository, change the workflow's `VITE_BASE_PATH` to `/`.

## Firebase configuration

Do not put Firebase Admin credentials, service-account JSON, API secrets, Resend webhook secrets, or other server credentials into GitHub Pages/static assets.

Browser Firebase configuration may be supplied through Vite environment variables, but Firestore/Storage rules and backend authorization remain the security boundary.

## Rules tests

The rules test uses `@firebase/rules-unit-testing@5.0.1`, which is compatible with Firebase 12.x. Start the Firestore emulator in another terminal, then run:

```powershell
npx firebase-tools emulators:start --only firestore
npm run rules:test
```

If `firebase-tools` is already installed globally, the `npx` prefix is optional.
