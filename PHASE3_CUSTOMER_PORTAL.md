# Phase 3 — Customer Portal + Secure Sign-Off

## Implemented

The legacy `public/client.html` functionality has been decomposed into a React/Vite customer workspace while preserving the existing Firestore schema.

### Customer routes

- `/customer` — overview
- `/customer/tickets` — ticket history and filters
- `/customer/tickets/:ticketId` — ticket details
- `/customer/request` — new service request
- `/customer/assets` — known assets derived from service records
- `/customer/billing` — linked quotes and invoices
- `/customer/profile` — customer profile
- `/signoff?ticketId=...&token=...` — secure sign-off

## Security model

Customer ticket creation requires both `requesterUid` and `customerId` to equal the authenticated Firebase UID. Customer ticket updates remain limited by Firestore rules to scheduling/address/attachment fields and `updatedAt`.

Attachments use the existing `ticket-attachments/{ticketRef}/...` storage rule and remain customer-owned unless staff access is granted by the existing rules.

The secure sign-off page never writes directly to Firestore. It calls the Netlify `authorise` function with the expiring one-time token. The server validates token hash, expiry, ticket status and one-time-use state, then performs the transaction that closes the ticket and creates the audit record.

## Compatibility

The legacy `public/client.html` and `public/clientsignoff.html` remain in the repository for rollback and existing-link compatibility. New sign-off links generated by the `authorise` function default to `/signoff`. `SIGNOFF_PATH` can still be overridden server-side during rollout.

## Known environment limitation

The build environment used for this migration could not complete an npm registry install, so a full Vite production bundle was not generated here. The source passed Phase 1, Phase 2, Phase 3 integrity checks and TypeScript JSX transpilation checks. A connected CI/developer environment should run `npm install` and `npm run build` before deployment.
